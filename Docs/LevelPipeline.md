# Сборка уровней: дизайн

Статус: предложение, 19.10. Цель — править карты руками в редакторе без
морока и без риска, а скрипты оставить помощниками.

## Что сейчас не так

- **Сборщики стирают ручную работу.** `build_zerog.py`, `build_range.py` и
  `build_test_room.py` удаляют карту и строят её заново. Ручная правка
  выживает только до следующего прогона. `build_ship.py` делал так же; теперь
  (шаг 1) он отказывается работать без `JAM_REBUILD_SHIP_WIPES_HAND_EDITS=1`, а
  `Ship-Blockout.md` говорит «Не пересобирать».
- **«Свои акторы» определялись по классу, а не по владельцу.** `jam_flyers.py`
  удалял любые зоны летунов, в том числе поставленные руками (cf5d295). Теперь
  он заменяет только свои: с тегом `Jam.Flyers` или с меткой из своих списков.
  Остальные сборщики владения не знают.
- **Карта — один двоичный файл.** Два человека не могут править корабль
  одновременно. Каждая правка — новые 1.8 МБ в LFS (17 версий за два дня), а
  квота LFS у аккаунта почти занята.
- **Скрипты материалов перетирают настройку.** `jam_flesh.materials()` при каждой
  сборке пишет параметры во все `MI_Jam_*`, так что подстроенная руками кожа
  планетоида откатывается.
- **Игра угадывала устройство уровня.** Часть уже явная (см. таблицу в D):
  старт после смерти — `PlayerStart` с тегом `Cabin` (без него — первый
  найденный и предупреждение в лог), `CargoTotal` считается по `AJamCargo` на
  `StartPlay`, у зон `Priority`. Осталось: каюта «самая большая коробочная
  зона» — в пробах (`jam.Ship.Probe`, пробы рук и хвата), три лампы пульта —
  в коде (`JamShipParts.cpp`).

  Добавил руками зону или старт — что-то может тихо сломаться, и никто об этом
  не сообщает.

## Принципы

1. **Карта — источник истины, редактор — основной инструмент.** Скрипт помогает,
   но картой не владеет.
2. **У каждого актора один владелец**: человек или генератор. Генератор трогает
   только своё.
3. **Скрипт сначала показывает, потом делает.** По умолчанию — отчёт о том, что
   изменится; запись только с `--apply`.
4. **Уровень говорит игре о себе явно** (теги, маркеры), а валидатор проверяет,
   что карта цельная.
5. **Один актор — один файл.**

## Решение

### A. Один актор — один файл (External Actors)

На всех картах включается «Use External Actors» — то же, на чём живёт World
Partition, но без разбиения на ячейки. Каждый актор хранится своим маленьким
пакетом в `Content/__ExternalActors__/Jam/Maps/<карта>/`, а `.umap` остаётся
лёгким: настройки мира и список.

Что даёт:
- правка двери — один файл на килобайты, а не 1.8 МБ;
- Ник и скрипт (или Ник и ты) правят разные акторы одновременно и сливаются без
  конфликта;
- `git status` показывает, какие именно акторы изменились;
- блокировка LFS — на актор, а не на всю карту.

Ловушки, известные по MindKore:
- **Сироты.** Удалённый актор оставляет файл, если удаление не сохранили.
  Сохранять нужно все изменённые пакеты, а не только уровень.
- **Python.** Перемещение существующего актора сохраняется, только если перед
  ним вызван `actor.modify()`.

Конвертация однократная, в редакторе. Её делают, когда Ник запушил и не правит
корабль; потом все подтягивают. Включение режима для не-WP карты и вид команды в
UE 5.8 нужно проверить в редакторе до конвертации.

### B. Генераторы с владением по тегу

Каждая скриптовая часть уровня — модуль `Scripts/level/<имя>.py`. Его функция
`desired(world)` возвращает список того, что должно стоять: устойчивый ключ,
класс, место и свойства. Общая точка входа:

```
UnrealEditor-Cmd ... -ExecutePythonScript="Scripts/jam_level.py <карта> <модуль>... [--apply]"
```

- У акторов модуля два тега: `Gen:<модуль>` (владелец) и `GenKey:<ключ>`.
- `jam_level.py` сравнивает желаемое с акторами, у которых есть `Gen:<модуль>`:
  - недостающие создаёт;
  - изменившиеся обновляет;
  - лишние удаляет.

  Акторы без тега не трогает никогда. Без `--apply` печатает таблицу «создать /
  обновить / удалить» и ничего не сохраняет.
- **«Забрать себе».** Хочешь подвинуть сгенерированный актор руками — сними с
  него тег `Gen:` (в Details → Tags). `GenKey:` остаётся, поэтому генератор
  видит, что ключ занят человеком, и не создаёт копию.
- Карты-стенды (`ZeroG`, `Range`, `TestRoom`) — это просто набор модулей.
  «Пересобрать» значит применить все модули: стенд обновится, а поставленное
  руками останется.
- Первые модули:
  - **flyers** — зоны летунов;
  - **planet-features** — кратеры и пробки по `planet_layout.json`;
  - **range-targets** — стены и цели тира.

  Модули стендов переносятся из нынешних сборщиков.
- Общие функции (`V`, `R`, `spawn`, `block`, `label_text`, «создать материал
  один раз») — в одном `Scripts/jam_build.py`, вместо четырёх расходящихся
  копий.
- Перед `--apply` скрипт отказывается работать, если у карты есть
  незакоммиченные изменения, которые сделал не он: это чья-то ручная работа.

### C. Ассеты: создать один раз, перенастраивать явно

Материалы и инстансы скрипты по умолчанию только создают, если их нет.
Перезаписать параметры числами из Python — флаг `--retune`. Пересобрать граф
мастера — `rebuild=True`, отдельным запуском редактора, как сейчас. Тогда ручная
настройка кожи переживёт любую сборку.

### D. Уровень описывает себя явно, валидатор проверяет

Вместо догадок в коде — пометки на карте:

| Код угадывал | Будет |
|---|---|
| каюта — самая большая коробочная зона (сейчас — только в пробах) | зона с тегом `Jam.Cabin` |
| старт после смерти — любой `PlayerStart` | `PlayerStart` с тегом `Cabin` — **сделано** |
| `CargoTotal = 6` в коде | считается по `AJamCargo` на карте — **сделано** |
| воздух — первая найденная зона | у зоны `Priority`; при равенстве выигрывает меньшая — **сделано** |
| цели пульта — три лампы в коде | маркеры целей на карте, пульт собирает их при старте |

`jam.Level.Check` — проба без рендера, которую запускают после ручной правки и
перед коммитом. Она печатает PASS/FAIL по каждому пункту:
- ровно один `PlayerStart` с тегом `Cabin`;
- у каждой пробоины есть зона чистки;
- у каждой цели есть док или пробоины;
- пересекающиеся зоны имеют разный приоритет;
- двери шлюза требуют ключ скафандра;
- зоны летунов лежат в воздухе;
- нет дубликатов меток и файлов-сирот;
- все ассеты, на которые ссылается карта, существуют.

### E. Работа вдвоём

- Перед правкой карты — `git pull`, после — сохранить всё и закоммитить
  изменённые файлы акторов.
- Настройка LFS для свежего клона — `Scripts/setup_git.ps1` (README), он же
  задаёт `lfs.setlockablereadonly false`. Иначе все `.uasset` придут только
  для чтения (строка в README есть; `jam_build.save()` теперь падает с
  ошибкой вместо тихого несохранения).

## Порядок и цена

| Шаг | Что | Цена | Когда |
|---|---|---|---|
| 1 | `build_ship.py` отказывается работать без явного флага; `Ship-Blockout.md` — ссылка на правило | 0.2 ч | сделано (`JAM_REBUILD_SHIP_WIPES_HAND_EDITS=1`) |
| 2 | Конвертация всех карт в External Actors | 0.5 ч + окно, когда Ник не правит | до следующих правок карт |
| 3 | `jam_level.py`, теги владения, отчёт перед записью; перенос `jam_flyers` и деталей планетоида | 2–3 ч | до конца джема |
| 4 | Явные пометки уровня и `jam.Level.Check` | 2–3 ч | до конца джема (совпадает с находками ревью про респаун, груз и цели) |
| 5 | Создание материалов «один раз» и `--retune` | 0.5 ч | вместе с шагом 3 |
| 6 | Перенос сборщиков стендов в модули | 2 ч | после джема |

Решить до шага 2: удобно ли Нику окно на конвертацию корабля и остаются ли
стенды скриптовыми (шаг 6) или тоже переходят на ручную правку.
