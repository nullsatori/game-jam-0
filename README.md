# game-jam-0: космомусор

Игра для двухдневного геймджема. Тема — **Trash**, обязательный предмет —
**Rocket**. Проект на Unreal Engine 5.8 (C++). Часть систем перенесена из
MindKore: взаимодействие, механизмы, физика предметов, стекло, попадания,
замедление времени. Поверх них написана невесомость.

## Концепт

**Одной фразой.** Невесомость, поле космического мусора и разбитый корабль.
Собираешь корабль из того, что летает вокруг, а двигаешься только по законам
Ньютона: толчками, отдачей стволов и бросками мусора.

**Опоры.**
1. **Физика — это и есть игра.** Скорость сохраняется. Толкнул лёгкое —
   улетело оно, толкнул тяжёлое — улетел ты. Стоит каждое касание:
   столкновения, рикошеты, урон от собственного удара на скорости.
2. **Стволы — двигатель.** У каждого выстрела есть отдача. Пистолетом
   аккуратно подталкиваешь себя, снапой улетаешь через полполя.
3. **Лут физический.** Большую деталь корабля не кладут в инвентарь. Её
   тащат на себе (захват физически связывает тебя с ней), буксируют на тросе
   или толкают к кораблю.
4. **Видно, куда полетишь.** Пока целишься толчком, выстрелом или броском,
   рисуется путь с первым рикошетом. На этом держатся головоломки.

**Петля.**
- Каждые 10 секунд: прицелился, толкнулся или выстрелил, полетел, поймал опору.
- Каждую минуту: нашёл деталь, придумал, как её сдвинуть, довёл до корабля.
- За игру: стыковочная зона корабля набирает детали (`n/N`), корабль собран —
  улёт.

**Ресурсы и угрозы.** Кислород: дыхание и маневровые. Стволы кислород не
тратят. Ещё угрожают удары на скорости и, позже, каскады мусора.

**Простые пространственные головоломки — заготовки.**
- **Бильярд.** Выбить деталь другим предметом, угол подсказывает линия
  рикошета.
- **Противовес.** Деталь не сдвинуть толчком: цепляешь трос и сам
  отталкиваешься от станции.
- **Слингшот.** Трос на вращающийся обломок, вовремя отпустить.
- **Тормоз мусором.** Кислорода на маневровые нет, бросаешь предмет вперёд
  по курсу.
- **Шлюз по таймеру.** Пролететь с деталью можно только с разгона.
- **Стекло-шорткат.** Разбить иллюминатор брошенным баллоном и пролететь
  насквозь.
- **Баллон-ракета.** Пробитый баллон тащит прицепленную деталь.
- **Каскад.** Провести деталь через рой, ничего не задев.

**Открытые вопросы** (решаем вдвоём, ответ записываем сюда):
- Почему ты собираешь мусор в космосе. Рабочая рамка: своя ракета развалилась
  на орбите, обратно лететь не на чем.
- Есть ли враги или соперники (дроны-уборщики, кооп/PvP) или только среда.
- Финал и длина: сколько деталей, одна большая зона или цепочка зон.
- Визуальный стиль: low-poly, палитра, Земля на скайбоксе.
- Название.

## Открыть и собрать

1. Нужен UE 5.8 и Visual Studio с C++. Перед первым clone установить Git LFS
   (см. ниже).
2. Собрать модуль редактора из PowerShell:

   ```powershell
   & "C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat" MKJamStarterEditor Win64 Development -Project="<путь>\MKJamStarter.uproject" -WaitMutex
   ```

   Или ПКМ по `MKJamStarter.uproject` → Generate Visual Studio project files →
   собрать `MKJamStarterEditor` в Development Editor.
3. Открыть `MKJamStarter.uproject`.

Пересобрать карту скриптом (редактор без окна; после скрипта он закрывается
сам или через `unreal.SystemLibrary.quit_editor()`):

```
UnrealEditor-Cmd.exe <путь>\MKJamStarter.uproject -ExecutePythonScript="<путь>/Scripts/build_zerog.py" -unattended -nop4 -nosplash -nullrhi
```

Модуль называется `MindKore` (папка `Source/MindKore`): так перенесённый код,
`MINDKORE_API`, `LogMindKore` и пути `/Game/MindKore/...` работают без правок.
Наш новый код — файлы `Jam*.h/.cpp` в той же папке.

Сборка на сдачу: Platforms → Windows → Package Project (Shipping). До этого
выставить стартовую карту игры в Project Settings → Maps & Modes.

## Как работаем вдвоём

**Роли** (впишите себя):
- satori — …
- Ник — …

Код из сессии Claude приходит коммитами в `main` с ПК satori. Пушит
satori.

**Ветки.** `main` всегда собирается и запускается. Маленькие изменения идут
сразу в `main`. Большие или рискованные — в `feature/<что>`, слить, когда
работает. Перед работой: `git pull`. Push — маленькими кусками и часто, не
копить день.

**Ассеты и карты — только под блокировкой** (раздел LFS ниже).
- Два человека не правят один `.uasset` или `.umap` одновременно: слить их
  нельзя.
- Главная карта делится на подуровни, у каждого свой хозяин. Например,
  `Lvl_Game` (persistent, только ссылки), `Lvl_Game_Layout` (геометрия,
  загадки), `Lvl_Game_Art` (декор, свет), `Lvl_Game_Audio` (звук).
- Второй вариант — включить у карты One File Per Actor: тогда каждый актор
  лежит отдельным файлом и блокируется отдельно.
- Новый арт — в `Content/JamArt/<раздел>/`. Системные ассеты
  `Content/MindKore`, `Content/Jam` без нужды не трогаем.

**Задачи.** Короткий список «делаю сейчас / дальше / сделано» держим в
GitHub Issues (или в чате). Один человек — одна задача в работе. Закрыл —
написал, как проверить.

**План на 48 часов** (дедлайн джема — вписать):
1. **День 1, первая половина.** Ощущение движения: стволы с отдачей, числа
   толчка, захвата и троса подкручены руками. Серый блок-аут одной зоны.
2. **День 1, вторая половина.** 3–4 головоломки на сером блок-ауте, корабль и
   детали заглушками. Игра проходится от начала до конца.
3. **День 2, первая половина.** Арт: корабль, детали, мусор, скайбокс. Звук
   и музыка: тишина вакуума, звук через скафандр, слои трека от собранных
   деталей.
4. **День 2, вторая половина.** Полировка, меню и финал, сборка Shipping,
   проверка на чистой машине, сдача. За 3 часа до дедлайна — только фиксы.

**Режем первым, если не успеваем:** каскады мусора, замедление времени,
дробовик, вторая зона.

## Арт и Git LFS

Все двоичные файлы проекта (`.uasset`, `.umap`, `.fbx`, `.wav`, `.png` и т. д.,
полный список в `.gitattributes`) идут через Git LFS. Код, конфиг и
документация — обычным git. Арт команды кладётся в `Content/JamArt/`, пути
пакетов `/Game/JamArt/`. Ассеты, закоммиченные до перехода на LFS, остались в
истории обычного git, а их текущие версии уже в LFS.

**Один раз на машине.** Установить [Git LFS](https://git-lfs.com) (идёт с
Git for Windows) и выполнить `git lfs install`. После этого `git clone` и
`git pull` сами скачивают файлы LFS.

**Блокировки.** Все `.uasset` и `.umap` помечены `lockable`: после checkout
они только для чтения, пока их не заблокируешь. Двоичный ассет нельзя слить,
поэтому правит его один человек:

```
git lfs lock "Content/JamArt/Ship/SM_Ship_Hull.uasset"
# правка в редакторе, сохранение, commit, push
git lfs unlock "Content/JamArt/Ship/SM_Ship_Hull.uasset"
git lfs locks            # кто что держит
```

Если редактор пишет, что файл только для чтения, значит его не заблокировали.

На машине, где скрипты сами пересобирают карты, режим «только для чтения»
можно выключить для этого клона: `git config lfs.setlockablereadonly false`.
Блокировки при этом остаются, их надо брать руками.

В UE можно поставить плагин «Git LFS 2» (Project Settings → Source Control):
он блокирует ассет сам при checkout.

**Квота.** LFS на GitHub считается на аккаунт владельца репозитория: 10 ГиБ
хранения плюс трафик, который тратит каждый clone и pull. Аккаунт уже занят
другим проектом примерно на 8,7 ГиБ, поэтому:
- текстуры не больше 2K (лучше 1K), без 4K и несжатых исходников;
- исходники (`.blend`, `.psd`, `.spp`) в репозиторий не класть, только
  импортированные `.uasset` и при необходимости `.fbx`;
- перед push смотреть `git lfs ls-files -s`.

## Ограничения стартера

Из MindKore не перенесены:
- оружие и руки;
- враги и ИИ;
- реакция тела (ragdoll);
- камера бодикама;
- Mover/ChaosMover;
- PhysicsControl.

Сторонних паков нет. Эффект и звук разбития стекла пока пустые (см.
[Glass](Docs/Glass.md)). Внешний вид и ощущение невесомости проверяются
только руками: автоматические прогоны шли без рендера.
